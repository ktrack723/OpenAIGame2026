# 혜성 방문 · 특이점 제거 · 조르그 폭발 개편 · 가스 행성 존속 · 지구 추진기

## 배경

**① 후반에 굴릴 공이 마른다.** 이 게임은 "행성을 밀어서 요새에 처박는" 당구인데, 큐볼을
보충하는 경로가 둘뿐이고 둘 다 판 안에서는 거의 안 돈다:

- `system.reinforce` — **판이 열릴 때 한 번**만. 판 도중에는 아무것도 안 온다.
- `game.stepHive` — 모함이 살아 있을 때만. 모함은 4판부터 오고, 부수면 그걸로 끝이다.

그래서 한 판 안에서 공을 다 소진하면(충돌로 부서지고, 태양에 떨어지고, 파편이 되고)
다음 판이 열릴 때까지 **판을 굴릴 수단 자체가 없다**. 표적은 남아 있는데 칠 공이 없는
판은 난이도가 아니라 벽이다.

**② 특이점은 걷어낸다.** 다섯 태그 중 유일하게 "아무것도 안 통한다"는 태그라, 판에
있으면 그 자리가 통째로 죽는다.

**③ 조르그가 부서지는 그림이 일반 행성과 같다.** 지금은 `destroy` fx 하나를 둘이
나눠 쓰고, 차이는 `big: true` 플래그 하나(소리만 갈린다)다. 화면에서는 목성이 부서지는
것과 요새가 부서지는 것이 같은 주황 화구다 — 이 게임의 유일한 보상이 배경 사건과
구분이 안 된다.

**목표** — 판을 굴릴 공이 판 도중에도 들어오게 하고(혜성), 죽은 태그를 걷어내고(특이점),
"조르그를 부쉈다"가 화면에서 즉시 읽히게 한다(빛기둥 2단 폭발).

## 확정된 설계 결정

| 질문 | 결정 |
|---|---|
| 혜성 주기 | 정기 방문 + 굴릴 공이 모자라면 주기 가속 |
| 지구 충돌 코스 | 스폰 시 미리 재서 피한다 (혜성은 순수한 보급이다) |
| 모성 | **부술 수 있게 만든다** — 난사를 버티며 치는 역전 판을 연다 |

`role === 'void'` 분기가 하나라도 남으면 영영 안 도는 죽은 코드가 된다.

종류는 `UNSTABLE_STAGE` 하나만 남는다(`forcedType`). 초엘리트는 `zorg: true`라
빛기둥 폭발을 자동으로 탄다.

**주의 하나** — `reinforce`에서 3판의 강제 중립 1기를 넣던 유일한 근거가 `VOID_STAGE`였다.
그 줄이 사라지면 "굴릴 공이 넉넉한 판에는 중립이 아예 안 온다"가 되는데, **그 자리를
혜성이 대신한다**(B). 그래서 A와 B는 같이 들어가야 한다.

`grep -rn "void\|absorb" src --include=*.js | grep -v vendor` 로 잔여 참조 0을 확인한다
(`void main()` 셰이더 문자열 · `void 0`은 무관하므로 눈으로 가른다).

## B. 혜성 — 지나가는 큐볼

### 규칙 한 줄

> 카이퍼 벨트 **바깥에서 안으로** 거의 일자로 뚫고 지나간다. 벨트에 안 튕긴다 —
> 이 판에서 벨트를 무시하는 유일한 천체다. 나머지는 전부 다른 공과 같다:
> 중력을 받고, 핵에 밀리고, 부딪히면 부서지고(체력 1), 광선에 녹는다.

### 진입선 — 충격 파라미터로 짓는다

방향과 위치를 따로 뽑으면 태양을 정통으로 지나는 선이 나온다. 그래서 **태양에서 직선까지의
거리(b)를 직접 고른다**:

```
b   = rE × rand(COMET_B)          // 태양 ~ 진입선 거리. rE = 지구의 지금 궤도 반경
dir = rand(0, 2π)                 // 진행 방향
n   = dir ± π/2                   // 그 직선의 법선
pos = n̂·b − d̂ir·(beltR + COMET_LEAD)
vel = d̂ir · COMET_SPEED
```

- `COMET_B = [0.55, 1.7]`는 **요새 대역(0.55~1.6 rE)과 같은 띠**다 — 혜성은 반드시
  싸움이 벌어지는 자리를 지난다. 따로 요새를 겨눌 필요가 없다.
- 태양 근점은 안쪽 극단(b = 0.55 rE)에서도 ≈330 GU로 코로나(R_STAR 195) 밖이다 —
  혜성이 제 발로 태양에 빠지는 일은 없다.
- 굴절: b = 0.55 rE에서 ≈15°, b = 1.7 rE에서 ≈5°. **"거의 일자"가 계산으로 성립한다.**
  (중력을 안 받게 만드는 게 아니다 — 빨라서 안 휘는 것이다.)
- 체류 시간 ≈ 64초(1판) ~ 90초(10판). 시한(640~1000초) 안에서 여러 번 온다.

### 지구 충돌 코스 회피

지구를 등속으로 놓고 상대 운동의 최근접 거리만 본다(혜성이 서너 배 빠르므로 이 근사로
충분하다). `COMET_EARTH_CLEAR × (지구 판정 원 + 혜성 판정 원)`보다 가까우면 그 선을
버리고 다시 뽑는다 — 최대 12회, 다 실패하면 이번 차례는 거른다.

### 새 파일 `src/game/comet.js`

`laser.js`와 같은 자리다: 순수 계산 + 스텝 함수만 두고 `game.js`는 얇게 부른다.

```js
export function spawnComet(rng, bodies, earth, aMax, tag)  // → body | null
export function stepComets(game, dt)                       // 스폰 시계 + 퇴장
```

천체는 반드시 `makeBody`로 만든다(hidden class 규율 — `body.js` 머리 주석):
`{ type: 'comet', role: 'comet', hp: 1, comet: true, nameKey: 'planet.comet', name: 'C/<태그>' }`

### 벨트 예외 (`game.bodyBounds`)

```js
if (b.comet) {
  const out = b.pos.x * b.vel.x + b.pos.y * b.vel.y > 0     // 바깥으로 가는 중인가
  if (r > this.beltR + CFG.COMET_EXIT && out) b.alive = false   // 조용히 퇴장
  continue                                                   // ← 벨트 반사를 건너뛴다
}
```

퇴장은 **연출도 문구도 없다**(격파가 아니다). 태양 낙하(`r < R_STAR + 15`)는 그대로
적용된다 — "나머지는 동일하게"가 그 뜻이다.

### 예측선과의 정합

`aim.js`의 벨트 처리는 전부 **미사일** 것이고, 예측 sim은 천체에 벨트 반사를 애초에
안 돌린다. 그러므로 혜성은 예측선에서도 실제와 같이 굴러간다 — **손댈 곳이 없다.**

## C. 폭발을 둘로 가른다

### 지금

`destroy` fx 하나를 넷이 나눠 쓴다(`damage` l.1156 · `laserEvent` l.937 · `tickDoom`
l.1352 · `killBody` l.1166). `big: true`는 소리만 가르고 그림은 똑같다.

### 바꾼 뒤

| | **조르그** (요새·모함·모성) | **일반 행성** |
|---|---|---|
| 박자 | **2단** — 예열 0.45초 → 폭발 | 1단, 즉시 |
| 그림 | 중심에서 **사방으로 빛기둥**, 폭발에 십자 네 갈래 | 화구 + 흙먼지 |
| 색 | 흰 코어 + 장미(요새 `0xff2b3f`) / 자홍(모함·모성 `0xe879f9`) | 주황·호박·적갈 (지금 그대로) |
| 링 | 예열에 **수축** 링 → 폭발에 팽창 링 3겹 | 팽창 링 2겹 |
| 파편 | **없다 — 통째로 증발한다** | 파편 4~9개 + 붉은 연기 (지금 그대로) |
| 흔들림·섬광 | `SHAKE_MAX`, flash 0.9 | 지금의 0.6배로 낮춘다 |
| 소리 | `zorgCharge` → `destroyZorg` | `destroy` |

빛기둥은 **조르그가 부서질 때만** 뜬다. 그림 하나가 곧 표식이라, 화면 구석에서 터져도
"판이 한 칸 줄었다"가 색과 형태로 읽힌다.

### 게임 쪽 (`src/game/game.js`, `src/game/body.js`)

1. `body.js` 기본값에 `dying: spec.dying ?? 0` 추가.
2. `game.js`에 발행 지점을 하나로 모은다:

```js
// 조르그는 두 박자로 터진다: 빛기둥(예열) → 폭발. 나머지는 한 박자다.
blastFx(b, rMul = 1.8) {
  if (b.zorg) {
    b.dying = CFG.ZORG_BLAST_LEAD
    this.addFx({ kind: 'zorgCharge', x: b.pos.x, y: b.pos.y,
                 r: hitRadiusOf(b), hive: b.role === 'hive' || b.mothership })
  } else {
    this.addFx({ kind: 'destroy', x: b.pos.x, y: b.pos.y, r: b.radius * rMul })
  }
}
```
   네 호출부를 전부 이 함수로 바꾼다(지구는 지금처럼 `earth: true`로 따로 간다).
3. `tick(dtFrame)`에 `stepDying(dtFrame)` — **실시간**이다. 마지막 요새를 부수면
   `won`이 되어 게임 시계가 멎으므로(`effTimeScale` 0), 인게임 초로 재면 그 폭발이
   영영 안 온다. (`stepWarpIns` · `stepDodgeCool`이 실시간인 것과 같은 이유다.)
   0이 되는 순간 `{ kind: 'destroy', zorg: true, hive }`를 발행한다.
4. 조르그는 파편을 안 남긴다 — `killBody`의 기본값을
   `shatterIt = !b.zorg && cause === 'collision'`로. (덤으로 후반 판의 파편 노이즈가 준다.)
5. **`recordKill`·`win()`은 죽는 순간 그대로 돈다.** 폭발만 0.45초 뒤다 —
   승리 패널은 `won`으로부터 1500ms 뒤에 뜨므로(`Victory.OPEN_DELAY`) 폭발이 그 안에
   들어간다. 잔상까지 보이게 하려면 `OPEN_DELAY`를 1900으로 올린다.

## D. 모성을 부술 수 있게 (독립 페이즈 — 위험도가 다르다)

셋과 달리 이건 **규칙이 바뀐다**: 예전의 시한 종료는 확정 패배("싸움이 아니라 통보")였다.

### 계측이 설계를 바꿨다

처음 계획은 "난사를 버티며 모성을 친다"였다. **16시드 계측이 그 길을 닫았다**:
난사가 시작되면 지구는 **중앙값 2초**를 버틴다(DOOM_GAP 0.22초 · 다섯 발에 한 발이
정조준 · 광선은 1~2초에 도달). 버틸 시간이 없으므로 버티며 칠 시간도 없다.

그래서 창을 **난사 앞으로** 옮겼다.

### 최종 설계

- `DOOM_WARP` 1.6 → **40초**. 모성이 워프해 들어와 총구가 달아오르는 동안이 창이다.
  도착 시 요새와 같은 충전 신호(`laserCharge` fx)를 띄워 "아직 안 쐈다"를 보여 준다.
- 그동안 **조준·발사가 열려 있다** — `canAim` · `fire()` · `hud.observing`에서 doom 가드를 걷었다.
- 다만 **판이 안 멈춘다**: doom 중 조준 모드는 `DOOM_AIM_SCALE`(0.5)로 흐른다.
  이 게임에서 판이 안 서는 유일한 구간이고, 그 자체가 "정상적인 판이 아니다"를 말한다.
- `DOOM_HP` = **1**. 모함(5)보다 낮다 — 어려운 것은 단단함이 아니라 40초라는 창과
  "핵이 안 통한다"는 제약이다. 핵은 여전히 안 통하되 **폭풍은 터진다**(모성 옆의 공을
  밀어 붙이는 수가 성립해야 계획이 가능하다).
- 부수면 `doomBroken()` — 난사가 그 자리에서 멎고 판을 이긴 것으로 친다.
  `recordKill` **다음에** 부른다(모성 격파도 "난사 중의 파괴는 전과가 아니다" 규칙을
  그대로 타야 문구가 하나로 남는다).

계측된 창: 모성 도착 → 지구 소멸까지 **42초**(예열 40 + 난사 2). 대부분의 판은
그래도 진다 — 미리 그 근처에 공을 붙여 둔 판만 산다.
(모성 자리는 예측 가능하다: 지구 각도 +0.4 rad, 반경 min(벨트×0.8, rE×2.4).)

## 새 상수 (`src/game/config.js`)


## 작업 순서

1. **A — 특이점 제거.** 가장 넓고 가장 얕다. 여기부터 해야 B가 깨끗한 태그 표 위에 앉는다.
2. **B — 혜성.** A가 비운 자리(3판의 강제 중립)를 그대로 메운다.
3. **C — 폭발 2단 분리.** A·B와 안 얽힌다. 렌더 작업이 제일 크다.

커밋은 페이즈마다 하나씩, 이 저장소의 기존 메시지 문체(한글 한 줄 요약 + 근거)를 따른다.

# 덧붙임 — 가스 행성은 터져도 안 죽는다

## 배경

같은 문제의 다른 얼굴이다. 혜성이 "판 도중에 큐볼이 마른다"를 고쳤다면, 이건
**판의 지형이 마르는 것**을 고친다: 가스 행성은 유폭하면 그 자리에서 사라졌다.
태양계의 가스 행성은 목성·토성·천왕성·해왕성 — **판에서 제일 큰 넷**이다.
그 넷이 스치듯 맞은 한 방에 통째로 없어지면, 남는 것은 소행성뿐인 판이다.

## 규칙

유폭이 하는 일은 이제 **미는 것 하나뿐**이다. 그 공 자신은 **체력 1**을 잃는다.
체력이 3이니 세 번까지 터뜨릴 수 있고, 세 번째에 비로소 부서진다 — 그때의 파괴는
다른 공과 똑같은 경로를 탄다(`damage` → `blastFx`). "터졌다"와 "부서졌다"가
서로 다른 사건으로 갈린다.

## 함께 따라온 것 (규칙이 하나로 남게)

- **가스 행성도 핵에 밀린다** (`game.detonate` · `siegeDetonate`). 예전에는 임펄스를
  건너뛰었는데 그때는 유폭이 곧 소멸이라 밀 대상이 없었기 때문이다. 살아남는 지금
  안 밀면 "핵은 민다"는 대전제의 유일한 예외가 된다. 예측선도 같이 고쳤다
  (`aim.impactInfo`의 dv=0 목록에서 volatile을 뺐다) — 예측이 거짓말하면 안 된다.
- **충돌 유폭도 튕긴 뒤에 터진다** (`onPlanetCollision`). 같은 이유다.
- **쌍 쿨다운을 유폭 판정에도 건다.** 이게 없으면 터진 뒤에도 겹쳐 있는 두 공이
  다음 스텝에 또 터진다 — 한 번의 접촉이 기관총이 된다. 당구 판정이 쓰는 것과
  **같은 창**(`HIT_COOLDOWN` / 지구는 `EARTH_HIT_COOLDOWN`)이라 "한 번의 만남은
  한 번"이 두 규칙에서 같은 뜻이 된다.
- LCD의 연쇄 줄과 정보창·도감 문장에 **남은 체력**을 넣었다(다섯 언어). 이 태그를
  쓰는 계획의 전부가 "몇 번 더 터뜨릴 수 있나"이기 때문이다.

## 계측

| 항목 | 바꾸기 전 | 바꾼 뒤 |
|---|---|---|
| 무인 900초 × 12시드, 가스 48기 중 소멸 | 21기 (43.8%) | 22기 (45.8%) |
| 같은 조건에서 유폭 횟수 | 16회 (한 판 최대 2회) | **40회** (한 판 최대 7회) |

소멸률은 그대로인데 유폭은 2.5배다 — 노린 그대로다. 같은 판이 같은 만큼
정리되면서, 그 과정에서 **터지는 사건은 훨씬 자주 일어난다.** 한 판 최대 7회는
가스 행성 넷이 900초를 굴러 낸 값이라(기당 1.75회) 기관총이 아니다.

규칙 검사 8항목: 핵 직격 후 생존 · 체력 딱 1 · 유폭 연출은 뜨고 파괴 연출은 안 뜸 ·
파편 없음 · 제 몸도 밀림 · 세 번째에 부서짐 · 유폭 3회 전부 발생.

# 덧붙임 2 — 지구 추진기: 겨눠지면 켜지고, 필요한 만큼 태운다

## 문제

"카이퍼 벨트 근처에서 회피 버튼이 안 먹힌다." 재현해 보니 벨트만의 문제가 아니라
**모든 반경에서 창의 뒷부분이 통째로 죽어 있었다**(20시드 × 반경 4단 × 충전 잔여 8지점):

| 충전 잔여 | 90 | 75 | 60 | 45 | 30 | 20 | 10 | 5 |
|---|---|---|---|---|---|---|---|---|
| 버튼 켜짐 (지구 ×1.0) | 89% | 100% | 100% | 100% | 100% | 93% | **14%** | **0%** |
| 버튼 켜짐 (지구 ×3.8) | 100% | 100% | 100% | 100% | 100% | 100% | **0%** | **0%** |

원인은 **예측 게이트**다. 세기가 고정(Δv 2.5)이던 시절, 버튼은 "지금 태우면
광선이 닿는 순간 회랑을 벗어나 있는가"를 물어 그 답이 참일 때만 켜졌다. 세기가
고정이면 그게 유일하게 정직한 방법이었지만, 그 결과 **늦게 누르면 아무것도 못
하는 버튼**이 됐다. 게다가 안전장치(`dodgeSafe`)가 세기를 깎다가 **0.17까지**
내려간 표본이 있었다 — 그런 판에서는 창이 아무리 남아 있어도 영영 안 켜진다.

## 바꾼 것

1. **게이트를 걷었다.** 겨눠지고 있으면(충전 중이고 빗나갈 예정이 아니면) 켜진다.
2. **방향은 태양 반대쪽 하나.** 예전에는 쏠 선에 직각으로 밀었는데, 그 방향은
   광선마다 달라서 어디로 튈지 미리 못 읽었다. 이제 언제나 밖으로 민다.
3. **세기가 결과를 보증한다.** 고정값에서 시작해 **조준선에서 판정 반경 ×3만큼
   확실히 벗어날 때까지 키운다**(`burnDv`). 안전장치는 이제 세기를 지우는 장치가
   아니라 **더 키우지 못하게 막는 상한**이고, 기본 세기 아래로는 절대 안 내려간다.

새 상수: `EARTH_BURN_CLEAR: 3` (판정 반경의 몇 배를 "확실히"로 볼 것인가) ·
`EARTH_BURN_STEP: 1.35` (키우는 배율) · `EARTH_BURN_MAX: 20` (절대 상한).

## 계측 (같은 조건)

| | 90 | 75 | 60 | 45 | 30 | 20 | 10 | 5 |
|---|---|---|---|---|---|---|---|---|
| 버튼 켜짐 (전 반경) | 100% | 100% | 100% | 100% | 100% | 100% | **100%** | **100%** |
| 실제로 회랑 이탈 (×1.0) | 100% | 100% | 100% | 93% | 100% | 71% | 86% | 77% |
| 실제로 회랑 이탈 (×3.8) | 92% | 81% | 76% | 76% | 72% | 72% | 24% | 0% |

Δv는 상황에 따라 2.5~15.1로 스스로 커진다(평균 8~9).

**남는 한계는 물리다.** 창이 5초밖에 안 남으면 상한까지 태워도 48 GU를 못 비킨다 —
버튼은 켜지고 재고는 닳는다. 게이트를 걷은 대가가 그것이고, 그 대신 궤도는 통째로
갈리므로 **다음 광선은 다른 판에서 맞는다.** 바깥 반경에서 이탈률이 낮은 것도
기하 때문이다: 총구가 안쪽에 있으면 광선이 거의 반경 방향이라, 반경 방향으로 민
변위는 조준선을 가로지르지 않는다(가로지르는 것은 진행 방향 성분뿐이다).

덤: `canThrust`가 더 이상 궤도 적분을 안 돈다 — 매 프레임 0.9ms짜리 예측이
0.55µs짜리 명단 검사가 됐다. 적분은 버튼을 실제로 누를 때 한 번(0.92ms) 돈다.

# 덧붙임 — 모성은 뜸을 안 들인다 (DOOM_WARP 40 → 2 · DOOM_HP 1 → 10)

## 배경

위 D에서 잡은 값의 전제는 "창은 난사가 아니라 그 앞의 예열"이었다. 그 결과가
**40초짜리 정적**이다: 모성이 워프해 들어온 뒤 붉은 링 하나가 조용히 수축하는
동안 화면에서는 아무 일도 안 일어난다. 시한을 넘긴 판의 마지막 장면이 그것이었다.

## 바꾼 것

- `DOOM_WARP` 40 → **2**. 워프인 연출(`WARP_TIME` 1.5초)이 끝나 무엇이 왔는지
  읽히는 데까지만 두고, 그다음은 전부 난사다.
- `DOOM_HP` 1 → **10**. 모함(5)의 두 배. 눈금이 "한 번 닿았나"에서 "몇 번이나
  처박았나"로 바뀐다 — 충돌 피해는 상대속도로 1·2·3이므로(`onPlanetCollision`)
  세게 친 공 넉 대면 넘어간다.

규칙 자체는 안 건드렸다: 핵은 여전히 안 통하고(`detonate`의 모성 분기), 폭풍은
그대로 터지고, 부수면 `doomBroken()`으로 판을 되찾는다.

## 계측 (헤드리스 8시드, 무입력)

| 항목 | 값 |
|---|---|
| 워프인 → 첫 발 | **1.98초** (= `DOOM_WARP`) |
| 첫 발 → 지구 소멸 | 중앙 **1.92초** (아홉 발째, 한 시드만 3.02초/열네 발) |
| 도착 → 판이 쓸려나감 | **약 4초** (예전 42초) |
| 체력 처리 | 3 피해 × 4 = 10 소진 → `doomBroken` → 판 되찾기 ✔ |
| 3 피해 × 3 (9) | 체력 1로 살아남는다 → `TIME_UP` ✔ |

## 남는 것

**시한을 넘긴 판은 그 자리에서 만드는 한 수로는 못 되찾는다.** 4초 안에 열 피해를
넣어야 하는데 탄 하나의 비행이 10~25초다. 되찾는 판은 **미리 공을 붙여 둔 판**뿐이고,
모성 자리가 예측 가능하다는 것(지구 각도 +0.4 rad, 반경 min(벨트×0.8, rE×2.4))이
그 계획의 유일한 근거다. 이걸 "그래도 손이 닿는 창"으로 되돌리고 싶으면 손댈 곳은
셋이다: `DOOM_AIM_EVERY`(다섯 발에 한 발인 지구 정조준을 성기게), `DOOM_GAP`(발 간격),
`DOOM_WARP`(한 박자를 서너 박자로).
