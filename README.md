# BISHOUJO RIZZ SIMULATOR 2077

키보드로 돌아가는 터미널 연애 **코칭** 게임. 당신은 연애하지 않는다 — 남을 연애시킨다.

> 2077년. 남성 위비와 여성 위비가 나라를 점령했고 출생률은 1 아래로 떨어졌다.
> 테크노킹 도람푸 3세의 특별 지시로 정부는 비밀 기관을 하나 세운다.
> 당신은 그 기관에 새로 배치된 요원이다.

```
npm start
```

키가 없어도 그냥 돌아간다. `ANTHROPIC_API_KEY` 를 넣으면 대화를 Claude 가 맡는다.

---

## 하는 일

의뢰인의 서류철을 읽고 → 옷을 입히고 → 대화법을 코칭하고 → 등을 떠밀어 내보낸 다음,
**옆에서 지켜보다가 아주 가끔 귓속말로만 개입한다.** 대화는 의뢰인과 상대가 알아서 한다.

| 단계 | 내용 | 입력 |
|---|---|---|
| 1. 서류철 | 의뢰인 6명 중 하나를 고른다. 사연·외모·성격·상대의 취향(일부만 공개) | 메뉴 |
| 2-1. 스타일링 | 상대 취향에 맞게 꾸민다 | 태그 (`가죽 재킷, 별자리 목걸이`) |
| 2-2. 코칭 | 어떻게 대화할지 지시한다. 그대로 시스템 프롬프트가 된다 | 자유 서술 |
| 2-3. 격려 | 연설. 사연을 정확히 짚을수록 자신감이 오른다 | 자유 서술 |
| 3. 문자 단계 | 6번의 주고받기. **개입 1회** | 귓속말 |
| 4. 대면 단계 | 8번의 주고받기. **개입 2회**. 수치는 그대로 이어진다 | 귓속말 |
| 5. 편지 | 며칠 뒤 의뢰인이 결과를 편지로 알려온다 | — |

### 두 개의 수치

- **분위기** — 대화 흐름이 자연스러웠는가. 취향 적중과 무관하다.
- **호감** — 상대의 취향을 만족시켰는가. 대화 흐름과 무관하다.

**분위기는 호감 증감의 배율**이다 (0 → ×0.65, 100 → ×1.25).
어색하게 말했지만 취향을 맞혔다면 분위기 −, 호감 + 가 정상이다.

### 이기는 법

1. **공개된 취향은 미리 심는다.** 스타일링과 코칭으로 화제를 깔아둔다.
2. **숨은 취향은 대화 중에만 드러난다.** 상대가 흘리는 힌트를 놓치지 마라.
3. **발견했으면 개입해서 알려줘야 쓴다.** 의뢰인은 긴장해서 스스로 눈치채지 못한다.
   이게 개입 기능이 존재하는 이유다.
4. **같은 얘기를 반복하면 값이 급감한다.** 넓게 훑어라.
5. **지뢰는 끝까지 비공개다.** 밟으면 크게 깎인다. 코칭에 `자랑은 하지 마` 라고 적어두면
   실제로 덜 밟는다 — 부정문을 구분해서 읽는다.

## 조작

| 키 | 동작 |
|---|---|
| `↑` `↓` 또는 `j` `k` | 메뉴 이동 |
| `Enter` / 숫자키 | 선택 |

### 실행 옵션

```
node game/main.js --help

  --client=<id>                  dohun/sera/minhyuk/gahui/taeo/haru

  --fast                         타자기 효과 끄기
  --no-color                     색 끄기
```

## LLM 모드

```bash
npm install                       # SDK 설치 (선택 의존성)
export ANTHROPIC_API_KEY=sk-...
npm start
```

세 개의 역할이 각각 한 번의 API 호출이다.

- **의뢰인** — 코칭·격려·개입을 받아 말한다. *상대의 취향 목록을 절대 보지 못한다.*
- **상대** — 자기 취향을 전부 알고, 가끔 힌트를 흘린다.
- **심판** — 의뢰인의 매 발언을 분위기/호감 증감으로 환산한다. 구조화 출력(JSON Schema).

모델은 `claude-opus-5` (`RIZZ_MODEL` 로 변경 가능).
**호출이 실패하면 그 턴만 오프라인 판정으로 대체된다** — 게임이 중간에 죽지 않는다.

> 의뢰인 프롬프트에 정답지가 새지 않는 것은 테스트로 강제된다
> (`test/engine.test.js` → "의뢰인 프롬프트에는 대상의 취향 정답지가 없다").

## 오프라인 엔진

키 없이도 게임 전체가 돌아간다. 생성기와 판정기가 분리돼 있고, LLM 엔진과 **같은 인터페이스**
(`{ text, topic, tier }` → `{ moodDelta, loveDeltaRaw, ... }`)를 쓴다.
그래서 `game/core/game.js` 는 어느 엔진이 붙었는지 알 필요가 없다.

자동 플레이 계측과 회귀 테스트도 전부 이 엔진 위에서 돈다.

---

## 자동 플레이 계측

```
npm run selfplay          # 5전략 × 3난이도
npm run balance           # 판수 늘려서
node tools/selfplay.js --verbose --strategy=expert --seed=7   # 한 판 상세
```

봇은 플레이어와 **완전히 같은 입구만** 쓴다. 공개된 서류철과 대화 중 알아낸 것만 보고
문자열을 만든다 — 숨은 취향을 훔쳐보지 않는다.

승률 (60판/칸, 고백 성공):

| 전략 | 쉬움 | 보통 | 어려움 |
|---|---:|---:|---:|
| 숙련 요원 (준비 + 개입) | 100% | 100% | 77% |
| 평범한 요원 (준비만, 개입 없음) | 100% | 88% | 50% |
| 날림 요원 (대충 한 줄) | 2% | 0% | 0% |
| 무준비 | 0% | 0% | 0% |
| 역효과 (지뢰를 밟는 준비) | 0% | 0% | 0% |

읽는 법:

- **깰 수 있다** — 제대로 준비하면 이긴다.
- **거저 깨지지 않는다** — 준비를 건너뛰면 어느 난이도에서도 못 이긴다.
- **개입이 실제로 일한다** — 어려움에서 77% 대 50%. 공개 취향이 하나뿐이라
  숨은 취향을 개입으로 살리는 것이 유일한 길이다.
- 어려움의 통과선(72)이 보통(76)보다 낮은 것은 봐주는 게 아니다. 공개 취향이 하나뿐이라
  **도달 가능한 호감 총량 자체가 낮다.**

이 숫자들은 `test/balance.test.js` 가 회귀 테스트로 못박아 둔다.
밸런스 상수를 건드리면 거기가 먼저 깨진다.

## 테스트

```
npm test      # 54개
npm run check # 문법 검사
```

- `test/core.test.js` — 난수 재현성, 서류철 구성, 텍스트 채점(부정문 포함), 터미널 폭 계산
- `test/game.test.js` — 루프 완주, 단계 전환, 개입 제한, 수치 범위, 시드 재현성, 6인 완주
- `test/engine.test.js` — LLM 구조화 출력 파싱, 실패 시 폴백, 요청 본문 규격, 프롬프트 정보 격리
- `test/balance.test.js` — "깰 수 있는가 / 거저 깨지지 않는가"를 승률로 검증

## 구조

```
game/
  main.js            진입점 · 화면 흐름
  core/
    game.js          상태 기계 (UI 도 봇도 이것만 조작한다)
    scoring.js       스타일링·코칭·연설·개입 채점, 고백 판정
    config.js        밸런스 상수 전부
    rng.js           시드 고정 난수 (Math.random 은 로직에 쓰지 않는다)
  engine/
    local.js         오프라인 시뮬레이션
    llm.js           Anthropic Messages API
    prompts.js       의뢰인 / 상대 / 심판 프롬프트
  data/
    clients.js       의뢰인 6명
    topics.js        화제 19종 + 지뢰 7종, 대사 은행
    letters.js       엔딩 편지
  ui/
    term.js          ANSI · 원시 키 입력 · 한글 폭 계산
    screens.js       화면 조립
tools/
  selfplay.js        자동 플레이 계측기
```

시드를 고정하면 판 전체가 재현된다 — 같은 시드는 같은 대사, 같은 수치, 같은 편지를 낸다.
